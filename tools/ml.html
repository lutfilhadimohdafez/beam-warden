What it detects
The attack's effect on the router's own telemetry — no adapter, no monitor mode

The BeamCraft attack forges beamforming-feedback (BFI) frames that mis-steer the AP's beam away from the victim. The victim then can't acknowledge the AP's frames, so the AP retransmits — and its own tx-retry / PER counters spike while MCS and throughput sag. Beam-Warden reads those counters straight from iw station dump, so it runs on any OpenWrt router with no capture adapter. (Counting the forged frames directly is cleaner but needs monitor-mode hardware many routers lack — so we detect the retransmit signature instead.)

The model, honestly
What we report vs. where the signal really is

We report a RandomForest on self-calibrated relative features (each metric as a ratio/z-score vs this network's own baseline), scored leave-one-RUN-out — hold out a whole capture run, so the number is "works on a network it never saw", not within-one-run. The forest's decision is distilled to calibrated thresholds the on-router package runs (no sklearn on the router).

Why this, not the earlier designs? First was an IsolationForest on raw 11-value telemetry — too weak at a strong link. Then a BFI-storm detector that counted the forged frames on-air — clean, but needs monitor-mode capture (a USB adapter, and a monitor VIF the AP's own radio won't deliver; many routers can't do it) so it isn't portable. This design reads the router's own telemetry — the attack's retransmit signature — so it deploys on anyone's OpenWrt router with no extra hardware.

Per-environment calibration
The one production concept

Every network has its own normal retry/PER — a quiet home is not a busy event hall. So instead of a fixed number, Beam-Warden learns this network's normal first, then flags a sustained spike above it. On a deployed router that is one command — beamwarden calibrate (run it once with the attack off) — after which beamwarden watch raises NORMAL/ATTACK for that network. No lab numbers baked in.

Results & honest status
What is proven, and what is still future work

82.1% leave-one-RUN-out across 4 real runs / 126 samples — past the ≥ 55% OBJ3 target on data from a run it never trained on. Per-held-out-run: [100, 48, 80, 100]. The low fold is the one noisy low-power run — the honest covert-attack weakness: when the attack doesn't degrade the link, telemetry barely moves. More conditions (distance / channel / load / hardware) would shrink that fold. The engine ships as a standalone OpenWrt package (openwrt/beamwarden — busybox + iw, no python/ sklearn, no adapter): calibrate learns the baseline, watch alerts. Validated running on the real AC2100.
